# Подключение витрины, кошелька и check-in

> Обновление: доступны Cookie сессии, единицы CUSTOM/CNY, подписки и розыгрыш Vessa,
> кабинет Vyce AI. Актуальные способы входа и ограничения —
> [в описании обновления](dashboard-update-ru.md). Ниже сохранено описание первого этапа.

Реализован первый общий адаптер семейства New API. Он обслуживает разные домены с этим
контрактом, независимо от API для генерации и выбранного CLI. Работа конкретного
авторизованного аккаунта SeekAI ещё не проверена; публичный статус проверен.

## Как подключить

1. В карточке нужного провайдера выбрать **«Подключить кабинет»**.
   При добавлении нового провайдера адрес сайта и токен можно ввести сразу
   в блоке **«Витрина и личный кабинет»**.
2. Указать адрес сайта, например `https://seekai.cc`. Разрешено вставить `/profile` —
   приложение сохранит origin сайта. Платформа для этого этапа — **New API**.
3. Если сайт предоставляет account access token, ввести его в поле **«Токен доступа
   к кабинету»** локально. Это отдельная авторизация кабинета; API-ключ для моделей
   не следует автоматически считать подходящим. Существующий токен можно выбрать
   через ссылку на секрет в локальном хранилище.
4. ID аккаунта необязателен. Он нужен некоторым старым версиям New API и дополнительно
   проверяет, что кошелёк принадлежит выбранному аккаунту.
5. Выбрать **«Сохранить и проверить»**. Карточка покажет кошелёк и check-in либо конкретную
   причину отсутствия данных. Без токена доступны публичный статус и те разделы витрины,
   которые сайт разрешает читать без входа. На SeekAI тарифы требуют авторизацию.
6. Выбрать **«Модели и цены»** на карточке провайдера. Подробности —
   [в инструкции витрины](model-storefront-ru.md).

### Вход через Cookie-Editor

Если access token кабинета отсутствует или не принимается сайтом, сессию можно перенести
вручную через расширение Cookie-Editor:

1. Открыть сайт провайдера в обычном браузере и войти в нужный аккаунт.
2. Не уходя с домена провайдера, открыть Cookie-Editor и выбрать **Export → JSON**.
   Лучше экспортировать cookies только текущего сайта, а не всего браузера.
3. В ProviderDock открыть настройки нужного провайдера → **«Кабинет»** →
   **«Импортировать Cookie-Editor»**.
4. Проверить адрес сайта. Если этот форк New API требует заголовок `New-Api-User`,
   указать числовой ID аккаунта.
5. Вставить экспорт и нажать **«Сохранить cookies и проверить»**.

Также принимаются форматы Header String и Netscape. Импорт всегда привязан к одному
выбранному провайдеру: cookies с чужого домена отклоняются, просроченные и небезопасные
значения не сохраняются. Секрет не возвращается в ответах dashboard и хранится локально
в Windows DPAPI. Cookie даёт доступ к аккаунту как активная браузерная сессия, поэтому
его нельзя отправлять в чат или публиковать. После истечения сессии нужно войти на сайт
заново и повторить экспорт.

Проверить все уже настроенные кабинеты безопасными GET-запросами можно командой:

```powershell
npm.cmd run check:balances
```

Команда не запускает модели и не выводит токены или Cookie.

ProviderDock не читает профиль браузера и не управляет формой входа: перенос выполняется
только из явно вставленного пользователем экспорта Cookie-Editor. Генерация account token
и автоматическое обновление короткоживущего JWT не выполняются.

### Где взять токен на SeekAI

В [профиле SeekAI](https://seekai.cc/profile) прокрутить до блока **«Безопасность»**,
нажать **«Токен доступа»** (`Access Token`). В появившемся окне кнопка выпуска называется
**«Перегенерировать»**. После подтверждения сайт покажет токен один раз: скопировать его
в локальное поле ProviderDock и выбрать «Сохранить и проверить». Поле ссылки на секрет
при первом вводе токена можно оставить пустым — имя создаётся автоматически; ID аккаунта
для текущего SeekAI необязателен.

Перегенерация заменяет прежний токен кабинета. Приложения, использующие старое значение,
потребуют обновления. Если действующий токен уже сохранён у пользователя, можно вставить
его без перевыпуска. Это управление токеном кабинета в профиле, а не раздел ключей моделей.

Путь и русские подписи проверены в опубликованном интерфейсе SeekAI 7 сентября 2026:
[компонент профиля](https://seekai.cc/static/js/async/5851.ef4eefd87d.js),
[переводы интерфейса](https://seekai.cc/static/js/index.172656cc78.js).
Приложение не выполняет выпуск или перевыпуск токена автоматически.

## Поведение

- Только пять известных GET: публичный `/api/status` без ключа; `/api/user/self` и
  `/api/user/checkin` с отдельным Bearer-токеном; `/api/pricing` и
  `/api/perf-metrics/summary` с токеном кабинета, если он указан. Обновление не вызывает модель и не
  получает награду. Перенаправления не выполняются, чтобы токен оставался на заданном сайте.
- Кошелёк хранит остаток квоты, расход и группу. USD показывается как единицы сайта
  только если статус сайта явно сообщает `quota_display_type: USD` и корректный
  `quota_per_unit`. Для других валют/неизвестной формулы показывается исходная квота.
  Нулевой баланс остаётся нулём, отрицательный остаток не скрывается.
- Check-in различает «можно забрать», «сегодня уже получен», «выключен» и «нет личного
  статуса». Публичное включение функции не подменяет личную доступность. Часовой пояс
  сайта не угадывается. Данные наград и месячных записей нормализуются; отдельный календарь
  в интерфейсе этого этапа пока не добавлен.
- Время проверки и устаревание видны рядом с балансом/check-in. При сбое текущий баланс
  неизвестен; последнее успешное значение показывается отдельно с его временем.
- Обновление по умолчанию раз в пять минут, только при работающем dashboard. Фоновая
  очередь обрабатывает до трёх кабинетов одновременно. Повторы одного текущего обновления
  объединяются, ошибки увеличивают интервал, `Retry-After` соблюдается даже при ручном
  повторе. После ошибки авторизации автоматический опрос этого кабинета приостанавливается.
- Смена подключения или сохранённого токена очищает предыдущие результаты; завершение
  старого запроса не записывает их поверх нового подключения. Отключение кабинета сохраняет
  API-профиль и ключ для генерации. Токен кабинета остаётся в хранилище секретов и может быть
  удалён отдельно, чтобы не затронуть другие подключения, использующие эту ссылку.
- Настройки и нормализованные снимки сохраняются в `portals/accounts.json` внутри
  `PROVIDER_DOCK_HOME`. Токены — в существующем SecretVault (Windows DPAPI), отдельно.
  Email, имена пользователей, привязки OAuth и сырые ответы кабинета не сохраняются.

Файловая очередь защищает параллельные изменения внутри одного приложения; несколько
независимых процессов ProviderDock, пишущих в один каталог данных, пока не координируются
межпроцессным замком. Используйте один dashboard на каталог данных.

## Основание контракта и проверка

Пути подтверждены [маршрутами upstream New API](https://github.com/QuantumNous/new-api/blob/main/router/api-router.go),
кошелёк — обработчиком [GetSelf](https://github.com/QuantumNous/new-api/blob/main/controller/user.go),
личный check-in — [контроллером](https://github.com/QuantumNous/new-api/blob/main/controller/checkin.go)
и [моделью check-in](https://github.com/QuantumNous/new-api/blob/main/model/checkin.go).
Bearer авторизация основана на [middleware New API](https://github.com/QuantumNous/new-api/blob/main/middleware/auth.go).
Изучено 7 сентября 2026; форки с другим контрактом могут потребовать отдельного варианта.

Автоматические проверки охватывают раздельные ошибки, 401/403/404/429, блокировку редиректа,
ограничения размера/времени ответа, нулевой/отрицательный/неизвестный баланс, ошибку ID,
общий адаптер для двух сайтов, одновременные обновления, TTL, смену ключа и сохранение
файла. В Chrome с синтетическим сервером пройден весь путь: ввод токена → сохранение →
кошелёк/check-in в карточке → отключение; поле токена очищается, API-профиль остаётся.

Итог этого этапа: `npm.cmd run typecheck`, `npm.cmd test -- --reporter=dot`
(352 теста, 54 файла), `npm.cmd run build` и `git diff --check` проходят.

Реальный запрос адаптера к `https://seekai.cc/api/status` без авторизации успешно вернул
настройки сайта. Личные endpoints кошелька/check-in без ключа не вызывались. `/api/pricing` и
`/api/perf-metrics/summary` без входа вернули 401. Платных генераций не было.

Следующие этапы: авторизованная проверка конкретного кабинета, поддержка других
платформ, согласованные тарифы и блокировка расходов. Загрузка стандартных тарифов
New API и опубликованной статистики уже подключена.
