# Запуск, активность и совместимость — 8 сентября 2026

Недоступные модели остаются в общем списке своего провайдера. В карточках и таблице
они выделены красным. Для исчезнувших из API моделей показано оставшееся время
хранения: 48 часов с первого подтверждённого исчезновения. Повторные обновления
не продлевают срок; вернувшаяся модель снова становится обычной записью.

## Запуск агента

Кнопка «Запустить» доступна в шапке каждой страницы, у провайдера и в карточках
моделей. Она открывает компактное окно с папкой, маршрутом, моделью и выбором CLI.
При запуске из модели провайдер и модель уже выбраны. Привязки проектов используют
это же окно. Раздел «Ключи и настройки» не изменён.

Auto выбирает Claude Code для Claude/Opus/Sonnet/Haiku и Codex CLI для GPT/Codex.
Для других семейств учитываются предпочтение провайдера, формат API и результаты
диагностики. Несовместимость, подтверждённая диагностикой, исключает соответствующий
CLI; Messages-only подключение использует Claude Code. Явный выбор CLI сохраняется.

В Windows скрытый служебный процесс создаёт отдельный видимый PowerShell через
системный conhost. Папка и аргументы передаются как JSON в окружении, а не многократно
вкладываются в командную строку: старый вариант превышал лимит Windows при длинных
аргументах. Для npm выбирается доступный CMD shim, чтобы политика PowerShell для
PS1 не мешала запуску. Ошибка или мгновенный выход сохраняются в открытом окне.

## Статистика

В активности доступны расход токенов по дням, успешные/незавершённые попытки,
кольцевая диаграмма текущих состояний и рейтинг использования моделей.
Есть фильтры провайдера и периода 7/30 дней; стоимость сохраняет исходную валюту.

Статусы сгруппированы по провайдерам. Каждый блок раскрывается отдельно: поиск,
по 20 моделей на странице и 24 почасовых сегмента наблюдений. Серый означает
отсутствие наблюдений. Это история запросов через ProviderDock, а не непрерывный
мониторинг всего трафика провайдера. Графики используют сохранённые данные;
открытие интерфейса не запускает генерации.

## API и завершение ответов

| CLI | Форматы upstream |
| --- | --- |
| Codex CLI | Responses; Chat Completions через адаптер |
| Claude Code | Messages; Chat Completions и Responses через адаптеры |

Auto использует недавние успешные запросы конкретной модели, диагностику и свежие
метаданные форматов из кабинета. Формат не выбирается по успешному запросу другой
модели. После HTTP 404/405/501 допускается альтернативный формат; принятый ответ,
таймаут, ошибка авторизации, 429 и частичный поток не вызывают повторную генерацию.

Переход Claude → Responses сохраняет роли истории и идентификаторы инструментов.
Терминальный снимок дополняет только ещё не отправленный текст; уже отправленные
дельты не дублируются. Некорректный или оборванный поток завершается явной ошибкой.
Messages без причины завершения не считается успешным; max_tokens/pause_turn
учитываются как неполные ответы, включая SSE.

Семантика событий проверена по [документации Responses streaming](https://developers.openai.com/api/docs/guides/streaming-responses).
Поведение окон Windows сверено с [документацией Microsoft о создании консоли](https://learn.microsoft.com/en-us/windows/win32/procthread/setting-window-properties-using-startupinfo).

## Проверка и пределы

Проверки: TypeScript, Vitest, сборка, браузерный сценарий
`node scripts/dashboard-ui-smoke.mjs` и реальное окно Windows через
`node scripts/terminal-window-smoke.mjs`. Последний проверяет видимую консоль
с неперенаправленными stdin/stdout и закрывает её после проверки.

Проверки API выполняются на контролируемых локальных ответах. Платные генерации
и интерактивные сессии CLI у всех внешних провайдеров не запускались. Поддержка
трёх форматов не гарантирует поддержку нестандартных расширений каждого сайта;
непредставимые возможности возвращают ошибку. Авторизованный кабинет NoFX по-прежнему
требует отдельного подтверждённого контракта, как описано в dashboard-update-ru.md.

Для применения к запущенному приложению перезапустите ProviderDock; его BAT-файл
собирает актуальный код перед запуском.
