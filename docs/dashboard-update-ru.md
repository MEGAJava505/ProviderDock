# Провайдеры и витрина — 8 сентября 2026

Вкладка «Модели и цены» оформлена по предоставленному примеру: компактная сетка,
название, вход/выход/кэш, тарифная группа с коэффициентом, задержка и статус.
Нажатие карточки (либо Enter/Space) открывает сведения справа. Остались поиск,
выбор провайдера и группы, переключатель карточек/таблицы. Цены за токены всегда
показаны за 1 миллион. Витрина разделена на блоки провайдеров, группы подписаны
именем своего провайдера. У моделей с оплатой только за запрос поля входа,
выхода и кэша полностью скрыты. Буквенные аватарки убраны.
Сортировка, фильтр «Показать все модели» и блок витрин сайтов убраны.

Названия провайдеров задаются независимо от URL при добавлении и редактировании.
Переключение Base URL ↔ URL/cURL сохраняет имя, адрес и ключ. Настройки кабинета
существующего провайдера открываются общей кнопкой «Настройки»: вкладки
«Провайдер» и «Кабинет» сохраняют черновики при переключении. Сайт находится рядом,
обновление кабинета — небольшой кнопкой внизу карточки.

## Расход токенов

Нажмите на блок «Токены»: история раскрывается в той же области статистики,
повторное нажатие сворачивает её. Стоимость вынесена в отдельный блок.
Можно выбрать дату и календарный день
или неделю с понедельника; границы рассчитываются в часовом поясе браузера.
История раскрывает сессии, клиента, провайдера, модель, вход, выход, чтение/запись
кэша, рассуждения и веб-поиск. Рассуждения входят в выход и не суммируются повторно.
Тексты задач не сохраняются. Покрытие — сохранённые запросы управляемых мостов
ProviderDock; внешние приложения и ручные диагностические генерации сюда не входят.
История ограничена последними 10 000 событиями хранилища, а не полным биллингом сайта.

## Панели и управление моделями

Провайдер открывается справа: кабинет, вертикальная история API и мини-витрина
с ценами, задержкой и состоянием каждой модели. Верхняя граница карточки зависит
от состояния: зелёная — стабилен, янтарная — ограничения, красная — недоступен,
серая — нет проверки или выключен. Цвета не назначаются по имени провайдера.

Правая панель модели содержит вкладки «Обзор», «Производительность» и «API»,
базовые цены и таблицу групп с коэффициентами. «Отключить модель» убирает её из
витрины и выбора запуска. Восстановление: Настройки → Провайдер → Отключены вами.
Выбор хранится в `disabledModelIds` профиля; новые запуски обоих клиентов запрещены,
а резервные цепочки исключают отключённые модели. Управляемые мосты проверяют
актуальные настройки перед каждым новым запросом. Уже отправленный запрос не
отменяется; сессия, работающая напрямую с внешним API без моста ProviderDock,
требует перезапуска. Диагностика также пропускает отключённые модели.

Успешное обновление списка API фиксирует удаление модели. Карточка остаётся
с пометкой «Убрана из API» 48 часов с первой фиксации, затем исчезает. Отметка
сохраняется после перезапуска и повторных обновлений; возвращение модели в API
восстанавливает карточку. Ошибка авторизации или повреждённый ответ списка моделей
не считаются массовым удалением.

Модель, присутствующая в свежем списке API, но отсутствующая в свежей успешной
витрине сайта, помечается «Есть в API · скрыта на витрине». Это результат сравнения
двух списков, а не подтверждение успешной генерации; её проверка показана отдельно.
Устаревшие или недоступные витрины не дают такого вывода. Ручное отключение не
смешивается со скрытием на сайте.

## Баланс и валюты

Баланс округляется до двух десятичных знаков, тарифы сохраняют точность малых цен.
Валюта не подменяется: поддерживаются USDT в ручных тарифах, USD, CNY и собственные
единицы сайта. Если сайт передаёт USD-кредиты, они остаются USD, без неявного обмена
на USDT. По умолчанию тарифы показаны за миллион токенов.

У Bezhi (`beizhi.sylu.cc`) статус сообщает `quota_display_type=CUSTOM`, символ 🍊,
`quota_per_unit=500000` и `custom_currency_exchange_rate=1`. Поэтому 46 455 000 квоты
равны 92,91 🍊. Раньше CUSTOM не пересчитывался и интерфейс показывал сырую квоту.
Для CNY применяется `usd_exchange_rate`, для CUSTOM — `custom_currency_exchange_rate`.
Неизвестные курсы не угадываются; исходная квота остаётся квотой. Цены New API
переводятся в те же единицы сайта, а коэффициент выбранной группы применяется один раз.

Публичные настройки: [Bezhi](https://beizhi.sylu.cc/api/status),
[Vessa](https://vsllm.cc/api/status). Формула проверена также по опубликованному
[клиенту Vessa](https://vsllm.cc/assets/index-qw_VDgaP.js).

## Вход в кабинет

В форме кабинета доступны отдельный Bearer-токен и Cookie сессии браузера.
Кнопка «Импортировать Cookie-Editor» принимает экспорт текущего сайта в JSON,
Header String или Netscape и сохраняет только cookies, подходящие выбранному домену.
New API иногда требует ещё ID из `New-Api-User`; его можно указать рядом с экспортом.
Cookie сохраняется в DPAPI-хранилище,
в профиле остаётся только ссылка. Истечение сессии требует повторного входа.
ProviderDock не читает пользовательский профиль браузера и не управляет входом на сайт.
Редиректы с авторизацией не выполняются; обновление не получает награды и не покупает подписки.

**Vessa LLM:** `/api/user/self` — кошелёк, `/api/subscription/self` — подписки,
`/api/gwent/status` — розыгрыш, текущие/дополнительные попытки, время пополнения,
интервал и ёмкость. Значения берутся из ответа, правило «две попытки каждые три часа»
не зашито в код. Wallet Management и подписки доступны по ссылке
`/console/topup`. Обычный выключенный check-in не заменяет статус розыгрыша.

**Vyce AI** (названный в запросе Vyze): адрес в локальном профиле — `vyceai.com`.
Сайт использует Cookie `session` или сессионный Bearer JWT из `vyce_session`
в Local Storage. `/user/dashboard` передаёт `user.totalBalance` (USD), `tier`,
`tierExpiresAt` и модели с ценами/статусом. Из ответа сохраняются только нормализованные
данные; почта и API-ключи исключены. Отсутствующая квота не превращается в ноль.
Контракт проверен по [опубликованному клиенту](https://vyceai.com/assets/index-BZFr0Cav.js).

**NoFX:** публичный [сайт](https://nofx.one/en) подтверждает Daily Check-in.
Это другой кабинет с серверными действиями и сессией входа, а не New API.
Автоматическое чтение баланса и личного check-in **остаётся неподдерживаемым**;
его нельзя исправить вводом несуществующего Integration/OAuth Token.
В интерфейсе есть пояснение и переход на сайт. Нужен подтверждённый контракт
авторизованного кабинета для отдельной интеграции.

Авторизованные кабинеты Vessa и Vyce проверены на локальных фикстурах; реальные
сессии пользователя не импортировались и платные генерации не запускались.

## Доступность и проверка

Недоступность, ограничения и ошибки ключа выделяются красным с пояснением.
Ранее обнаруженные модели сохраняются в ограниченной истории: если свежий
успешный список API больше не содержит модель, она остаётся видна с предупреждением.
После возвращения предупреждение исчезает. Устаревшие проверки не считаются свежими.
Наличие модели в списке API не выдаётся за успешную генерацию.

Оформление использует [UI Tools](https://github.com/ui-layouts/ui-tools) как ориентир
для фона, цветовых акцентов и теней, без копирования компонентов и новых UI-зависимостей.
[application-skills](https://github.com/membranedev/application-skills) проверен;
его интеграции через Membrane для этой задачи не понадобились.

Проверки: TypeScript, полный Vitest, сборка и `node scripts/dashboard-ui-smoke.mjs`.
Браузерный сценарий проверяет названия, переключение настроек, сохранение ключей,
витрину, коэффициенты, правую панель, мобильный экран и пагинацию.
