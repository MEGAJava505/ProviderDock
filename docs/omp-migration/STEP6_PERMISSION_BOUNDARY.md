## Full-auto, resume and hard boundaries

Pinned settings define `always-ask`, `write`, and `yolo` in `settings-schema.ts:4023-4036`. CLI `--auto-approve/--yolo` is parsed in `cli/args.ts:279-280` and `main.ts:1443-1451` overrides `tools.approvalMode` to `yolo`; therefore the local runtime's explicit `always-ask` argv/policy is a managed-launch control, not proof that an arbitrary real invocation cannot use full-auto flags. No legacy full-auto permission is imported into ProviderDock.

Pinned OMP supports native session resolution through `main.ts:895-970` (`--continue`, `--resume`, `--fork`, `--session-dir`). ProviderDock's managed runtime always creates a fresh run home/session path and exposes launch/cancel/reconcile only; it does not expose native resume. Reconcile, repeat launch and transcript import are not native resume. **Native resume: NOT PROVEN / outside this package.**

`read` with an absolute path remains allowed by upstream. `fetch.enabled=false`, disabled discovery providers and `mcp.enableProjectConfig=false` are policy settings, not a Windows firewall or OS sandbox. User-level MCP, auto-discovery, extensions, eval/shell children, native binary behavior and OS egress require separate runtime/isolation proof.

This package uses synthetic data, loopback and `tests/support/omp-fake-child.mjs`; it does not run real `omp.exe`, paid Doctor, live v2, live homes/transcripts/keys, Bun/importer, cutover or commit/push/PR. Step 5 remains `BLOCKED/NOT PROVEN` per the M8 decision.
