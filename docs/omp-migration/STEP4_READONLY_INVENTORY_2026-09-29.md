## Следующий gate

Для VSLLM требуется диагностировать `no-text-output` без ослабления gate; возможные причины (лимит 16 output tokens, форма удалённого ответа, поведение модели) пока не подтверждены. До нового Doctor L3 `PASS` нельзя пересобрать честное v2 decision как готовое к пилоту. Публикация v2-файлов в живой профиль и один ограниченный реальный OMP-пилот требуют собственных решений. Для остальных 17 строк решение принимается по каждому профилю, без переноса результата VSLLM на них.

**Сверка контракта Responses, без платных запросов (29 сентября 2026):** [OpenAI Docs: reasoning](https://developers.openai.com/api/docs/guides/reasoning) указывает, что `max_output_tokens` включает скрытые reasoning-токены и при исчерпании лимита нативный API может вернуть `status=incomplete`, `incomplete_details.reason=max_output_tokens` без видимого текста. [OpenAI Docs: GPT-5.4 Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) указывает поддержку Responses и `reasoning.effort=none` по умолчанию. Текущий Doctor отправляет лимит **16** и отдельно классифицирует `failed/incomplete` как unsuccessful response; наблюдённый второй ответ попал в ветку `no-text-output`, значит сохранённая диагностика **не установила** штатный `incomplete` и не раскрыла форму ответа VSLLM. Поведение прокси VSLLM из документации OpenAI не следует. Для различения причин нужен один отдельно разрешённый ограниченный запрос, выводящий только `status`, `incomplete_details.reason`, счётчики usage и типы элементов `output`, без текста ответа, ключа и сырых headers. Даже лимит 128 не гарантирует видимый текст; до свежего Doctor L3 `PASS` gate пилота остаётся закрытым.
