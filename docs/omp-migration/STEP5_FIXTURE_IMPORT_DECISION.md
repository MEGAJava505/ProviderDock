# M8 — решение о fixture-импорте и безопасном повторе

Дата: **1 октября 2026**. Задание: [M8](archive/2026-10-01-m8-handoff.md); очередь: [глава 3](REMAINING_PLAN.md). Это дополнение к [блокеру Step 5](../omp-step5-import-blocker-2026-09-24.md), а не замена его истории.

## Решение и граница доказательства

**BLOCKED — исполнение fixture-импорта и автоматического повтора.** Для следующего отдельного решения выбран **кандидат A: Bun library API**, explicit synthetic source roots, отдельный target `sessionDir`, OS-изоляция **сети и файловой системы**. Сигнатуры для однократной записи найдены; безопасный end-to-end импорт и recovery **NOT PROVEN**. Статус `automatedFixtureImportFromNodeHarness: "unsupported"` не изменён.

Минимально недостаёт: разрешённого изолированного Bun-runner с зависимостями; error-bearing полного reconciliation вместо tolerant listing; проверенного сохранения operation marker до первой OMP-записи; verified-finalize manifest под межпроцессным владением. Наличие отдельных библиотечных методов не означает, что эта композиция уже реализована или проверена.

**Сделано только чтением исходников:** pin/probe, разбор маршрутов и таблица решений. Production-код, тесты и upstream не менялись. Никакие OMP-сессии, manifest импорта или исходные transcript в M8 не создавались и не читались. Нового fixture-кода нет: пока не доказаны prerequisites, RED→GREEN runtime-цикл не начинается.

### Два маршрута

**A — Bun library API, кандидат для отдельного разрешения.** Контракт однократного вызова:

1. Созданные оператором абсолютные synthetic roots `S_codex`, `S_claude`, существующий synthetic `C` (cwd), target `T` и fixture runtime-state `A` — раздельны, с неизменной привязкой при повторе. Source mounts read-only; `T/A` — owned writable. Никакой подмены глобального host `HOME`/`USERPROFILE`.
2. `new CodexSessionStore(S_codex)` либо `new ClaudeSessionStore(S_claude)`. `info: ForeignSessionInfo` задаётся fixture runner: `source`, вымышленный `id`, проверенный абсолютный `path` внутри нужного `S`, synthetic `cwd=C`, фиксированные `created/modified`; `list()` не нужен.
3. Библиотечный вызов — `persistForeignSession(store, info, {sessionDir: T, suppressBreadcrumb: true})`. Не передавать `fallbackCwd`: это ещё один путь filesystem-check/`moveTo()` (`foreign-session-import.ts:48-49`); cwd fixture должен существовать заранее.
4. До этого вызова нужны gates ниже и operation marker из M8.2. После него — `getSessionId()/getSessionFile()` (`session-manager.ts:1948-1953`), завершение записи и **новое чтение файла**, а не проверка только возвращённого manager. Исключение записи/закрытия, timeout или неизвестный исход ведут в reconciliation, не в повтор.

Краткий call graph:

```text
explicit store + explicit fixture info
  -> store.load(info) -> SessionManager.inMemory(cwd)
  -> [будущий adapter: appendCustomEntry(operation marker)]
  -> persistForeignSession: appendCustomEntry(foreign_session_import)
  -> persistCopy({sessionDir:T, suppressBreadcrumb:true})
  -> fresh ID + cloned entries -> FileSessionStorage.writeTextAtomic
  -> [будущие strict readback/reconciliation + verified-finalize]
```

Adapter может реализовать существующий `ForeignSessionStore.load()` делегированием в explicit store и добавлением своей метки до возврата in-memory manager. Это **предложение композиции существующих методов**, не новый параметр `persistForeignSession`, не изменение upstream и не уже реализованный wrapper. Нельзя добавлять метку только после `persistCopy()`: crash до неё оставит неидентифицируемую копию.

### Prerequisites до какого-либо fixture-run

1. **Runtime:** Bun **`>=1.3.14`** по `packages/coding-agent/package.json:83-85`, зафиксированная выбранная версия runner и совместимые заранее подготовленные workspace dependencies. Сейчас `Get-Command bun -CommandType Application` не находит Bun в `PATH`; это не утверждение об отсутствии любого Bun на диске. Ничего не устанавливалось и не запускалось.
2. **OS isolation до первого import:** отдельный проверенный контейнер/VM/эквивалент, запрет egress/DNS/inference для процесса и потомков; host homes/credentials/sockets не смонтированы, upstream/dependencies — read-only, только synthetic inputs и owned output/state доступны. Внутренний home sandbox должен быть пустым, synthetic и не связанным с host home; host `HOME`/`USERPROFILE` не менять. Нужны отдельное разрешение и наблюдаемая проверка этих границ, не mocked `fetch`, не пустой API key и не grep.
3. **Транзитивные побочные эффекты:** cwd, config, agent, blob, log/cache/temp directories и env discovery должны разрешаться только внутрь sandbox до загрузки utils. `PI_CODING_AGENT_DIR` сам по себе не блокирует `os.homedir()/.env`; named profile/XDG/ambient aliases также нельзя без проверки унаследовать (`packages/utils/src/dirs.ts:346-364,381-392`). Текущий M8 не доказывает замыкание всех transitive effects.
4. **Recovery до записи:** error-bearing полный scan/точечный readback, проверенный marker, постоянная binding roots→target scope, межпроцессное владение и verified-finalize. Эти seams описаны ниже, но не реализованы и не приняты. До их доказательства автоматический повтор **BLOCKED**.

Docker и WSL найдены как CLI в `PATH`, **не** как доступный изолированный runner. `docker info`/WSL enumeration в M8 не выполнялись; датированные отказы 29 сентября остаются историей в старом blocker, не новым диагнозом окружения. Отсутствие готового Bun-runner уже достаточно для BLOCKED; не нужно обходить запрет установкой или запуском.

### Идентичность, marker и строгий readback

**Синтетические обозначения:** source `C0 = fixture-codex-001`, относительный путь `sessions/fixture-codex-001.jsonl`; альтернативный `L0 = fixture-claude-001`. `H0` — hash исходных fixture bytes, `H1 != H0` — изменённые bytes. `N1/N2` — две разные новые OMP identities. `P0` — полный кортеж upstream provenance; `M` — существующий manifest.

`K0 = sha256([client, relativePath, H0, "fixture-provider", "fixture-account"].join("\0"))` — **точная формула** `transcript-import-plan.ts:201-210`, не обещание проверенного digest. Для Claude локальный `client = "claude-code"`, upstream `source = "claude"`; для Codex оба — `"codex"` (`manifestSchema :226`; `foreign-session-store.ts:3-4`). Source session ID и абсолютные source/target roots **не входят** в K. Их неизменную привязку обязан хранить/проверять будущий runner; одинаковый K в другом физическом target не разрешает новую запись.

**Предлагаемая устойчивая метка** `provider_dock_import_v1`: version, K, H0, targetScope, непрозрачная binding roots/target, pinned upstream commit. Она добавляется через `appendCustomEntry` в in-memory manager до его первой persistence и сохраняется в том же copy вместе с `foreign_session_import`. Provenance проверяется полностью: `source/sourceId/sourcePath/sourceCwd` совпадают с выбранным fixture; метка должна быть ровно одна и соответствовать этой provenance. Marker не содержит credentials, permissions, transcript body или tool arguments. Сама возможность сохранить custom entry доказана источником; crash-visible устойчивость метки **ещё не испытана**.

Требуемая, **пока отсутствующая в ProviderDock**, seam `reconcileFixtureImport(binding, K, M)`:

1. Принимает только заранее закреплённые trusted roots и неизменный manifest scope, source hash и владение **всем target + manifest**, а не только K. Никакой active/stale/чужой writer не должен оставаться незамеченным.
2. Возвращает отдельно `complete(matches)` либо `blocked(reason)`; не преобразует ошибки, неизвестные файлы, лимиты, disappearance или повреждение в `matches=[]`. Полностью перечисляет owned target, отличает подтверждённые final copies от временных/backup/неидентифицированных артефактов. Если authoritative final path/receipt потерян и distinction не доказан, результат **blocked**, не догадка по filename/mtime.
3. Для каждой рассматриваемой final copy читает заново через upstream parser/loader без `SessionManager.open`; требует непустой валидный header, `malformedRecords=0`, matching `N/K/H/P0/scope/binding`, unique entry IDs, корректные parent chains и выбранную ветку. Любая ошибка stat/read/parse/size limit, недоказанная полнота scan, неизвестная provenance или повтор marker — отказ.
4. Сравнивает с **независимым synthetic oracle** полный порядок/число сообщений, роли, значения synthetic text, tool-call IDs/arguments и связанный tool-result, cwd, timestamps, model metadata, сохранённую compaction/branch structure там, где fixture её содержит. `N` отличается от source ID; при recovery совпадает с уже записанным `N`, а не заново сгенерированным. Копия in-memory результата importer сама по себе не oracle.
5. Только после положительного readback и повторного source/hash + target verification под тем же владением выпускает evidence для отдельного `verified-finalize`. Тот атомарно/CAS переводит **точный** staged K в imported с тем же N и перечитывает manifest; потерянное владение или ошибка финализации оставляет исход неопределённым для нового reconciliation. Текущий `writeImportManifest()` не обходить.

Generic bounded filesystem enumeration + существующий upstream parser — возможные строительные блоки, **не реализованный/доказанный strict scan**. В частности, один дополнительный `stat(T)` перед tolerant listing не исправляет скрытые per-file ошибки или гонку. До error-bearing scan, artifact distinction и ownership proof безопасная реализация выбирает **BLOCKED**, даже когда положительное точечное чтение возможно.

## M8.3 — gate и точная следующая точка решения

**Следующее внешнее решение:** разрешить подготовку конкретного offline Bun + OS filesystem/network-isolated fixture runner **и** отдельную реализацию/проверку marker, strict reconciliation и verified-finalize из M8.2. Одного согласия «запусти Bun» недостаточно. Альтернатива — предоставить pinned публичный error-bearing/import API с теми же гарантиями; RPC prompt не альтернатива.

После такого решения, **до** первой записи: определить runner/image/dependency pin, неизменные roots/binding, доказательство отсутствия доступа к host homes и egress; затем RED→GREEN для каждого окна таблицы и реальный synthetic readback обоих клиентов. Для runtime-правок обязательны `npm run typecheck`, `npm run build`, полный `npm test` и отдельно фактический Bun fixture-run. Ни эта будущая последовательность, ни команды не выполнены и не авторизованы текущим M8.

Doc-only gate M8: свежий pinned probe, сверка HEAD/чистоты upstream, проверка локальных Markdown-ссылок и source-line references, `git diff --check`, сравнение только M8-diff с начальным snapshot и проверка сохранности остальных tracked/untracked изменений. Build/typecheck/полный suite для этого doc-only пакета не повторяются.

Платный VSLLM-запрос, live v2, реальный OMP-пилот, живые transcript/homes/ключи, cutover и commit/push/PR остаются **отдельными открытыми gates**. Общая миграционная `/goal` открыта. Итоговые фактические команды/exit и граница review — в [PEER_REVIEW.md](PEER_REVIEW.md).
