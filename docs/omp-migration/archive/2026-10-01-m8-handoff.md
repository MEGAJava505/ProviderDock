## M8.1 — доказать доступный маршрут, только статически

1. Повтори read-only pin/probe и проверь статус `.scratch/omp` без изменения checkout. Прочитай закреплённые `foreign-session-import.ts`, Codex/Claude stores, `session-manager.ts`, `session-listing.ts`, `session-loader.ts`, upstream fixture-тесты, а также локальные `src/migration/migration-manifest.ts`, `transcript-import-plan.ts`, `transcript-import-preview.ts`. Для каждого вывода укажи точный `file:line` и отдели факт исходника от предположения.
2. Сравни два допустимых маршрута: Bun library API с **явным синтетическим source root** и изолированным target `sessionDir`; либо поддержанный публичный OMP API, если он действительно есть в pinned source. Для каждого зафиксируй runtime, вызовы, побочные эффекты, readback, ошибки, требования к OS-level сетевой изоляции и то, можно ли воспользоваться им без изменения upstream контракта. Не приписывай `importFactoryHasNoFetch` всей транзитивной цепочке.
3. Выбери один доказуемый маршрут для будущего fixture-run или честно зафиксируй **BLOCKED** с минимальным конкретным prerequisite. Отсутствующий Bun, Docker/WSL или error-bearing readback — блокер, если безопасную замену не доказал исходник. Существующий `unsupported` не переименовывай в `supported` по одному статическому просмотру.

**Критерий M8.1:** решение содержит исполнимый после отдельного разрешения вызов/контракт с явными корнями и изоляцией либо точный список недостающих возможностей. Никаких «пустой picker + exit 0 = импорт».

## M8.2 — контракт восстановления до записи

На **синтетических идентификаторах** составь детерминированную таблицу решений для пяти окон: до записи OMP; после записи OMP, но до `staged → imported`; повтор после уже verified import; две найденные сессии с той же provenance; ошибка listing/readback или частичная/повреждённая target session. Отдельно разбери изменение source hash и конкурирующий запуск. Для каждого случая укажи проверяемые признаки, допустимое следующее действие (`continue once`, `already imported`, `block for reconciliation`) и что остаётся в manifest. Нельзя считать `listSessionsReadOnly() → []` доказательством отсутствия записи, если функция скрывает I/O-ошибку. `imported` допустим только после повторного чтения новой OMP session и сверки identity, provenance и ключевых структурных свойств; source originals остаются read-only.

Если pinned API не даёт надёжного error-bearing чтения или устойчивой метки, опиши конкретную недостающую seam и останови автоматический повтор как **BLOCKED**. Не пиши напрямую OMP SQLite/JSONL и не строй обходной импорт на предположении о его формате. Pure fixture-код добавляй только если уже доказан используемый контракт; для нового поведения сначала RED→GREEN, затем typecheck/build/полный тестовый gate.

**Критерий M8.2:** ни один сценарий потери/ошибки/двусмысленности не приводит к ложному `imported` или повторной записи без проверки; reviewer может восстановить каждое решение по source evidence и synthetic table.
