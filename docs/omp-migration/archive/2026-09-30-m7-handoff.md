## M7.1 — контракт и точный dry-run

1. Прочитай `src/diagnostics/provider-doctor.ts`, `src/core/providers/provider-http-request.ts`, существующий `classifyResponsesStructure()` и [спецификацию в Step 4 inventory](../STEP4_READONLY_INVENTORY_2026-09-29.md). Зафиксируй контракт отдельно вызываемого **однократного** запроса: профиль `vsllm`, модель `gpt-5.4-mini`, `openai-responses`, endpoint `responses`, `max_output_tokens=128`, константный минимальный input, `stream:false`, без tools и автоматического retry. Ограничь время и объём читаемого ответа, запрети HTTP redirect и проверь конечный origin до запроса; ошибку тоже нормализуй к конечным безопасным кодам.
2. Подготовь точный dry-run descriptor для будущего разрешения: origin/endpoint, модель, лимит, API auth-kind **только если он доказан маскированно**, число запросов, какие структурные поля сохраняются и что никакой диагностический результат не открывает pilot gate сам по себе. Dry-run не должен читать значение ключа или отправлять сеть. Если без разрешённого read-only пути auth-kind неизвестен, так и запиши.

## M7.2 — fixture-only исполняемый путь

1. До production-кода напиши минимальные RED-тесты на имеющемся тестовом seam: один синтетический API-профиль и fake `fetch`, счётчик вызовов `≤1`, API-auth из профиля и отдельная decoy portal cookie, отсутствие её в запросе, native `incomplete/max_output_tokens`, completed без текста, proxy-non-native и 401/429/5xx/timeout. Тестируй отсутствие prompt/response text, секретов, headers, request ID и абсолютных путей в публичном результате, ошибках и выводе. Проверяй, что Doctor `run()` и health snapshot не вызываются/не меняются.
2. Реализуй узкий opt-in путь поверх существующего `ProviderHttpRequestBuilder` и `classifyResponsesStructure()`. Он должен быть доступен для локального fixture-прогона и иметь однозначную будущую команду/вызов для **одного** live-запроса после разрешения. Нельзя вызывать его автоматически из Doctor, dashboard, preflight или запуска OMP. Нельзя печатать raw payload даже при HTTP/JSON ошибке. Не добавляй новое постоянное хранилище для результата.
3. Запусти GREEN на фиктивных данных и точный dry-run. Фактический VSLLM-запрос **не выполняй**; если финальный live путь пока невозможно сделать безопасным или проверить auth-kind, остановись с конкретным blocker вместо угадывания.

**Приёмка:** локальный fixture доказывает максимум один исходящий вызов, правильную границу API/portal credentials, только allowlisted summary и отсутствие изменения health/route gate. Dry-run показывает пользователю точное действие для отдельного решения, без значения ключа и без сетевого эффекта.
