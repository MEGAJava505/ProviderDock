## M5-R.1 — пакет из текущего исходника, не из накопленного `dist`

**Область:** `package.json`, `scripts/package-safety-smoke.mjs`; при необходимости один небольшой build/pack helper под `scripts/`, не менять production routing/crypto/OMP.

- [ ] Зафиксируй RED **без чтения содержимого чужих файлов**: построй `src/**/*.ts` → ожидаемые JS-пути (учти действительный `tsconfig.build.json`/особые файлы) и покажи, что три перечисленных output-модуля есть в pack manifest, но отсутствуют в current source inventory. Отрицательная проверка должна ловить stale `.js` в принадлежащем тебе temp fixture даже если путь выглядит как разрешённый `dist/**/*.js` и `.gitignore` его не исключает. Одного root-level `decoy-secret.txt` недостаточно.
- [ ] Сделай локальную сборку/упаковку **source-matched**. Допустим clean staging build или безопасное обновление generated `dist`, но после штатного `npm run build` и непосредственно перед обычным локальным `npm pack` никакой orphan `.js` не должен попасть в пакет. Если нужен cleanup, сначала перечисли точные targets, проверь абсолютные пути внутри owned generated-output, сохрани возможность отката при неуспешной сборке; не делай широкий `rm -rf`/`Remove-Item` по вычисленному корню. В новом tarball должны присутствовать все актуальные runtime imports и package metadata. Сохрани `private:true`; `files` должен оставаться минимальным.
- [ ] Проверяй **набор путей**, не только число: package path set = ожидаемые emitted runtime `.js` + обязательные npm metadata, без orphan, `src/tests/docs/scripts`, generated maps/declarations и user material. Если TypeScript может эмитить пути не 1:1 к `.ts`, докажи маппинг другим строгим способом. Отдельно проверь, что сборка при ошибке не подменяет прежний работоспособный output частичным.
- [ ] Поставь детерминированную negative-проверку: в своём temp package/build fixture подложи `dist/<plausible-name>.js` и докажи, что acceptance становится RED/пакет его не несёт; верни GREEN. Не создавать fixture-файл в настоящем `dist` только ради теста, если можно проверить в owned temp-root.

**Приёмка:** обычный `npm run build` → `npm pack --dry-run --json --ignore-scripts` больше не включает три orphan, а persistent smoke отвергает новую stale output-регрессию. Не выдавай одно только расширение `.js` за доказательство безопасности содержимого.

## M5-R.2 — различать блокер npm cache и реальную ошибку пакета

**Область:** тот же package smoke, при необходимости fixture tests внутри него. Нет сетевых вызовов.

- [ ] Текущий `installRes.code !== 0` → `offline-cache-miss` зафиксируй как RED контролируемым fixture/инъекцией: воспроизведи как минимум cache miss, неверный tarball/manifest или иной install failure. Выход `BLOCKED` допустим **только** при проверенном offline-cache miss; неизвестный или package/integrity/install failure = `FAIL`/exit 1 без fallback и без печати raw stderr/путей/секретов. Если npm не даёт надёжно классифицировать причину, сообщи `BLOCKED:offline-install-unclassified`, но не утверждай `cache-miss` и не считай M5-R.2 принятым.
- [ ] Распаковка tarball с локальной зависимостью может остаться **отдельной fixture-проверкой** installed bin, но её PASS не переименовывает настоящий `npm install --offline` в PASS. Итоговый JSON должен иметь независимые `packageVerified`, `installedBinVerified`, `npmOfflineInstall` и общий verdict; `ok:true` только при выполненных обязательных пунктах и без `FAIL`. Печатай только allowlisted коды/счётчики.
- [ ] Запусти установленный CLI с изолированными `PROVIDER_DOCK_HOME`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR` (не меняй `HOME`/`USERPROFILE`), минимум `--help` и `providers list --json`, плюс один безопасный noninteractive fixture-only user path, выбранный после статической проверки CLI (например, локальное добавление/чтение **вымышленного** профиля без сети, если команда это позволяет). Сравни результат с source build; не маскируй ошибку установленного пакета source-smoke. Если такого пути нет, покажи конкретный blocker и не выдумывай проверку.
- [ ] Не заявляй «user home не тронут» по нынешнему `canaryScan(iRoots.dock, ["__provider_dock_should_be_empty__"])`: отсутствие маркера в **собственном** root не говорит о чужом home. Подтверди маршруты данных статическим разбором выбранных CLI-команд и проверкой записей только в temp roots; то, что без OS/filesystem isolation нельзя доказать отсутствие произвольного доступа к чужому home, честно отметь `NOT PROVEN`.

**Приёмка:** genuine offline install — PASS либо честный конкретный BLOCKED; malformed/integrity failure никогда не маскируется `cache-miss` или `ok:true`; installed bin действительно идёт из собранного tarball в temp roots.
