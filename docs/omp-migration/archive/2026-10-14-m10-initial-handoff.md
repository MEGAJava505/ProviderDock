# АРХИВ ПЕРВОНАЧАЛЬНОГО M10 — ЛОКАЛЬНАЯ ГРАНИЦА ПРАВ

> 14 октября 2026: первоначальное задание заменено расширенным [M10 — локальная часть всей главы 5](../AGENT_HANDOFF.md) по запросу пользователя. Это архив спецификации; выполнение прежнего M10 не заявлено. На момент замены отчёта M10 в PEER_REVIEW.md нет.

> **Старт:** 1 октября 2026, ветка `omp-integration`, HEAD `5025cb3`, накопительный dirty worktree. Сохраняй чужие изменения. [M9 архивирован](2026-10-01-m9-handoff.md), независимый вердикт — в [PEER_REVIEW.md](../PEER_REVIEW.md). Очередь и внешние gates — в [REMAINING_PLAN.md](../REMAINING_PLAN.md), глава 5 / Step 6, пункт 4.

**Цель:** перед реальным OMP-пилотом установить проверяемый локальный контракт прав для shell, write, network, MCP, extensions и настроек проекта. Текущий пилот запрашивает `read-only-pilot-no-sandbox`, генерирует политику `always-ask` с deny для части инструментов и запускает `--tools read --no-extensions --no-skills --no-rules --no-lsp`. Эти флаги и fake child сами по себе не доказывают OS-изоляцию или поведение настоящего `omp.exe`. Итог M10 должен точно различить локально доказанные ограничения, вывод из закреплённого upstream-кода и неподтверждённую границу реального процесса.

## M10.1 — контракт до реализации

Прочитай `src/clients/omp/omp-runtime.ts`, `omp-runtime-paths.ts`, `omp-credentials.ts`, `omp-config-compiler.ts`, `src/application/omp-launch-service.ts`, релевантные `omp-runtime`/integration тесты и закреплённый upstream из [Step 4 inventory](../STEP4_READONLY_INVENTORY_2026-09-29.md). Проверь pin и чистоту checkout через существующий probe; изучай только релевантные настройки/CLI/tool-loading места upstream. Составь короткую матрицу «возможность → локальный control → точное upstream-подтверждение → проверка → остаточный риск». Отдельно проверь порядок чтения project/global settings, `HOME`/`AGENT_DIR`, MCP и extensions, чтение вне проекта инструментом `read`, а также то, что старые full-auto flags не превращаются в новые разрешения. Не путай `always-ask` с OS sandbox.

До изменения кода назови наблюдаемый критерий для каждого найденного пробела. Сначала используй существующие проверки; добавляй RED fixture только если он доказывает новый риск, а не повторяет текущие assertions. Если доказать поведение без настоящего OMP нельзя, оставь его `NOT PROVEN` и не подменяй fake child утверждением о реальном бинарнике. Если локального дефекта нет, M10 может завершиться документированным решением без production-правок.

## M10.2 — минимальная проверка и исправление

Для воспроизводимого локального нарушения границы прав сначала получи RED на изолированном fixture-проекте, затем исправь только соответствующий путь и добейся GREEN. Сохрани fail-closed preflight, точный выбор provider/account/model, отдельное подтверждение пользователя, отсутствие auto-retry/fallback и прежний запрет запуска при неразобранных project settings. Никаких новых разрешений shell/write/network/MCP/extensions или скрытого импорта настроек в этом пакете.

Сверь фактический подготовленный argv/config/env и запреты preflight; при изменении runtime запусти целевые тесты, typecheck, build, полный `npm test` и `git diff --check`. При doc-only результате проверь pinned source и локальные ссылки, а неприменимые runtime gates так и назови. Browser smoke нужен только при изменении UI/HTTP пути. Просмотри task-only diff на debug/skip, секреты и неверные claims.

## M10.3 — решение и передача

Запиши матрицу и вердикт в `docs/omp-migration/STEP6_PERMISSION_BOUNDARY.md`: `LOCAL PROVEN` только для реально проверенного локального контракта, `STATIC UPSTREAM` для вывода из закреплённого исходника, `NOT PROVEN` для actual-binary и OS/network boundary. Обнови [план](../REMAINING_PLAN.md) и [runbook](../../omp-runtime-runbook-ru.md) только фактическим результатом. Step 4 остаётся без свежего Doctor PASS/live v2/реального пилота; Step 5 остаётся **BLOCKED/NOT PROVEN**.

В [PEER_REVIEW.md](../PEER_REVIEW.md) добавь `## M10 — отчёт исполнителя`: матрица доказательств, RED→GREEN при наличии кода, точные команды/exit/count, изменённые файлы и открытые gates. Перечитай раздел и отправь пользователю **дословно тот же итоговый ответ** в формате `Сделано / Проверено / Не проверено / Skills`. Отчёт исполнителя не является независимой приёмкой; общая миграционная цель остаётся открытой. Не выполняй платный VSLLM-запрос, публикацию live v2, настоящий `omp.exe`/OMP-пилот, Bun/importer, чтение живых homes/transcript/ключей, cutover или commit/push/PR без отдельного решения.
