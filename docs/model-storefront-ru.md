# Модели и цены провайдеров

> Текущий интерфейс: компактная витрина по новому примеру, сведения справа,
> только поиск/провайдер/группа в фильтрах, история токенов по дням и неделям.
> [Актуальное описание и ограничения](dashboard-update-ru.md).
> Ниже сохранены заметки о предыдущем этапе реализации.

В боковом меню откройте **«Модели и цены»**. Кнопка с таким же названием на карточке
провайдера сразу выбирает его в фильтре. Переключатель «Все провайдеры» возвращает
общую витрину. Есть поиск, карточки/таблица, сортировка цен, фильтры валюты, группы,
статуса и единиц 1 млн / 1 тыс. токенов. На странице выводится до 50 моделей.

## Подключение сайта

В форме **«Добавить провайдера»** теперь можно сразу заполнить два подключения:

1. Base URL и API-ключ — для запросов к моделям и получения списка через API.
2. Адрес сайта и токен кабинета — для витрины, цен, кошелька и check-in.

В адрес сайта можно вставить ссылку на `/pricing` или `/profile`. Поле токена
необязательно для публичных витрин; SeekAI требует авторизацию и для тарифов.
Если введён токен без адреса сайта, используется origin Base URL.
Платформа этого этапа — New API. ID аккаунта можно указать в дополнительных полях.

Токен кабинета сохраняется с отдельной автоматически созданной ссылкой в SecretVault.
Он не заменяет API-ключ модели. При редактировании пустые поля ключей сохраняют
текущие значения. Если меняется сайт кабинета, старый токен не переносится на другой
домен без ввода нового. Ошибка настройки кабинета после сохранения API-профиля
показывается отдельно, чтобы повторное сохранение не создавало второго провайдера.

У существующего провайдера используйте **«Подключить кабинет»** или **«Настройки»**.
Где взять токен SeekAI, описано в [инструкции подключения](provider-portal-setup-ru.md).

## Что означает витрина

- **Список вашего API** получается через endpoint моделей с ключом генерации.
  Модель из витрины сайта может отсутствовать в списке этого ключа. Эта разница видна
  на карточке; наличие в каталоге само по себе не означает успешную генерацию.
- **Цены сайта** поступают из `/api/pricing`. Для стандартного New API вход за
  1 млн токенов в USD-кредитах равен `model_ratio × 2`; выход и кэш используют свои
  коэффициенты. Групповой коэффициент применяется один раз. Нулевой коэффициент
  сохраняется, отсутствующий не заменяется единицей.
- По умолчанию показаны **базовые цены без группы**. Выберите группу своего
  API-ключа, чтобы увидеть тариф с её коэффициентом. Группа аккаунта не назначается
  автоматически: конкретный API-ключ может использовать другую группу.
- Тариф за запрос показан отдельно. Динамические формулы не выполняются и не
  заменяются условной фиксированной ценой. Режим «Пополнение», курсы и скидки не
  применяются. Неизвестная цена обозначена как отсутствие данных, а не ноль.
- **Скорость, задержка и успешность сайта** получаются из `/api/perf-metrics/summary`:
  токены в секунду, миллисекунды (в интерфейсе — секунды), процент успешных запросов
  за 24 часа. Это опубликованные агрегаты провайдера, не загрузка его серверов и не
  статистика только вашего аккаунта. В подробностях отдельно показан ваш трафик.
- **Подробнее** открывает таблицу базовых/групповых цен, чтение и запись кэша,
  заявленные API, контекст (если передан), источник и время обновления.

Обновление витрины выполняет только чтение метаданных. Модель вызывается только
при явном тесте или запуске агента. Тест потока и инструментов может выполнить до
пяти генераций.

## Обновление и ограничения

Кабинет обновляется раз в пять минут, с общей очередью, объединением одновременных
обновлений, увеличением интервала при ошибке и соблюдением `Retry-After`.
Кошелёк, check-in, каталог и статистика имеют отдельные результаты и ошибки.
Устаревшие данные помечаются. При неудачной загрузке новый каталог не считается
полученным: остаются модели, известные из API/настроек, и причина отсутствия цен.
При несовпадении ID аккаунта персональные тарифы и статистика также скрываются.

**Витрина пока не ограничивает списания.** Ручной тариф для локального учёта расходов
хранится отдельно и автоматически не перезаписывается ценой сайта. Жёсткие бюджеты,
сравнение с согласованным тарифом и блокировка подорожавшего маршрута требуют следующего
этапа. Авторизованный ответ конкретного аккаунта SeekAI в этой проверке не использовался.

## Проверка и источники

Нормализация основана на контрактах New API:
[ответ тарифов](https://github.com/QuantumNous/new-api/blob/main/controller/pricing.go),
[единицы цен](https://github.com/QuantumNous/new-api/blob/main/web/src/features/pricing/lib/price.ts),
[схема статистики](https://github.com/QuantumNous/new-api/blob/main/pkg/perf_metrics/types.go).
Реализация адаптера написана в ProviderDock; код сайта не выполняется внутри приложения.

Оформление использует [UI Tools](https://github.com/ui-layouts/ui-tools) как ориентир:
нейтральные поверхности, небольшие градиенты, тени и единые отступы. Это проект инструментов
для дизайна, а не установленный skill. Дополнительные UI-зависимости, внешние шрифты и
скрипты не добавлены.

Проверка: `npm.cmd run typecheck`, `npm.cmd test`, `npm.cmd run build`.
После сборки `node scripts/dashboard-ui-smoke.mjs` проверяет настоящий dashboard
в изолированном Chrome с данными в памяти: навигацию, витрину провайдера, поиск,
группы, карточки/таблицу, узкий экран, добавление двух ключей и их сохранение при
редактировании. Данные и токены тестовые; запросов к реальным моделям нет.
Скриншоты сохраняются в `.provider-dock/ui-smoke/` (не включаются в Git).
