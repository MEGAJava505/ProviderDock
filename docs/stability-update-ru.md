# Исправления стабильности и общая витрина

7 сентября 2026. Изменения в рабочем дереве, без публикации и платных запросов провайдерам.

## Реализовано

- Обычные маршруты Codex с выбором `auto` теперь тоже проходят через управляемый bridge.
- Native Responses JSON/SSE нормализуют `total_tokens`; неизвестный usage не выдаётся за нулевой.
- `output_item.done` без завершения всей Responses-генерации больше не превращается в успешный ответ.
- Завершённый Responses-поток закрывается после терминального события; дубли `output_item.done` подавляются, противоречия отвергаются.
- Chat-потоки для обоих CLI принимают завершающий usage после `finish_reason`, но не принимают новый текст/инструменты после завершения. После finish ожидание последнего usage ограничено одной секундой.
- Только в `auto`: отказ Responses endpoint с 404/405/501 разрешает одну попытку Chat на той же модели. Запоминание протокола относится к конкретному провайдеру и модели.
- Явно выбранный Chat у Claude Code соблюдается, включая GoRouter и модели с Claude в названии. Автоматическое обнаружение native Messages тоже хранится отдельно по моделям.
- Общий выбор портов исключает дополнительные запрещённые Fetch-порты 4190 и 6679. Это устраняет воспроизведённый случайный `fetch failed: bad port`.
- Doctor L3 сохраняет полный первый ответ в истории и проверяет одноразовую квитанцию из результата инструмента. Повтор инструмента и неверный ответ дают FAIL. `failed`/`incomplete` не считаются успешным окончанием Responses.
- В карточке модели появилась отдельная проверка «Поток и инструменты»: она использует реальные генерации только по нажатию, до пяти при определении протокола.
- Общая витрина объединяет модели всех провайдеров, поддерживает поиск, фильтры, сортировку цен и страницы по 50 записей. Одинаковые ID разных провайдеров остаются отдельными маршрутами.
- Наличие в `/models` теперь означает наличие в каталоге, а не успешную генерацию. Проверка модели считается устаревшей через 30 минут. Свежий успешный metadata-запрос не стирает ошибку генерации.
- Ошибки и 429 показываются по последним 30 локальным наблюдениям за 24 часа; это не загрузка серверов провайдера. Время HTTP-проверки каталога не выдаётся за задержку модели.
- Ручные тарифы можно редактировать из витрины. Они маркированы как не сверенные с сайтом и применяются к новым сессиям/записям расхода. Неизвестная цена платного серверного веб-поиска не подменяется нулевой стоимостью.

## Проверено

`npm.cmd run typecheck`, `npm.cmd test -- --reporter=dot`: 316 тестов, 51 файл.
Сценарии используют локальный HTTP и синтетические upstream-ответы. Для каждого из
Responses/Chat в Codex и Anthropic/Chat в Claude проверено: 15 одинаковых завершённых
запросов дают одну upstream-генерацию; остальные блокирует существующий TurnLedger.

Сборка `npm.cmd run build` и `git diff --check` также проходят. В отдельном headless
Chrome с синтетическим каталогом из 30 провайдеров / 180 моделей проверены показ первых
50 строк, поиск одной модели у 30 провайдеров, переход на вторую из четырёх страниц и
открытие редактора тарифа. Личные профили браузера и API-ключи для этого не использовались.

Это не доказательство устранения любого смыслового зацикливания. Если модель получает
изменённую историю и создаёт новые вызовы с новыми ID, нужен отдельный пример трассы.
Также bridge перед OmniRouter не восстанавливает состояние, уже утраченное внутри комбо.

## Границы совместимости

| Клиент | Responses upstream | Chat Completions upstream | Anthropic Messages upstream |
| --- | --- | --- | --- |
| Codex CLI | Да | Через перевод | Прямой перевод не реализован |
| Claude Code | Через перевод | Через перевод | Да |

Название модели не определяет её протокол. Opus через совместимый Chat endpoint может
использовать маршрут Codex; OpenAI-модель через Chat — маршрут Claude. Проприетарные
инструменты и скрытое reasoning-состояние могут не иметь эквивалента в другом протоколе.
Совместимость конкретного провайдера/модели требует проверки L3.

После перезапуска `ProviderDock.bat` сначала выберите один физический маршрут и проверьте
его; затем составляйте комбо из подтверждённых маршрутов. Эти изменения сами по себе не
меняют существующий профиль OmniRouter вне ProviderDock.

Следующим проходом добавлено [подключение кошелька и статуса check-in для New API](provider-portal-setup-ru.md).
Личные тарифы и автоматическое ограничение расходов пока не подключены. Текущая ручная
цена не защищает от повышения тарифа на стороне сайта. Остальные этапы описаны
в [отдельном ТЗ](provider-portals-and-spending-ru.md).
